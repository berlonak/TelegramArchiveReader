# Сборка с нуля на Windows (из одной папки)

**Нужно:** Windows 10/11, установленный **Python 3.10+** с командой `py -3`, интернет для первой установки зависимостей и одна папка Telegram Desktop, содержащая **`result.json`, HTML и все медиа рядом**. Не надо указывать две папки.

**Язык сообщений.** Скрипты и окна пишут по-русски, если Windows на русском (а также украинском, белорусском или казахском), иначе по-английски. Выбрать язык явно: в CMD выполни `set TGARCHIVE_LANG=ru` (или `en`) и запусти `.bat` из того же окна. English version of this guide: [WINDOWS.md](WINDOWS.md).

1. Скачай исходники (`git clone` или на GitHub *Code → Download ZIP*) и распакуй их отдельно, например в `D:\tgarchive-builder`. Убедись, что в ней лежат `START-HERE.bat` и `bundletool.py`.
2. Сделай **отдельную резервную копию** исходного экспорта. Скрипт по умолчанию *перемещает* исходную папку на **том же диске** в новый `TelegramArchive-ready/exports/first-export` ради экономии места на диске. Это не копирование и не резервная копия. Оригинальные байты файлов не меняются, но **исходная папка сменит путь**.
3. Дважды кликни `START-HERE.bat`. Укажи **один путь**, например `D:\TelegramExport` (в ней должен лежать `result.json`). По умолчанию пакет будет собран рядом в `TelegramArchive-ready`. Если там уже есть **готовая** сборка, не перезапускай импорт; используй её или выбери другой `BundlePath`. Если осталась папка от незавершённого запуска, см. раздел восстановления ниже.
4. Если бэкап уже есть, подтверди перемещение словом `ПЕРЕМЕСТИТЬ` (при английском языке сообщений — `MOVE`; для режима копирования — `КОПИРОВАТЬ` / `COPY`). **До перемещения** откроются два окна установки пароля (не короче 12 символов): вставляй через **Ctrl+V**, не через Shift+Insert в CMD. После подтверждения скрипт перенесёт экспорт, построит SQLite/FTS и проверит JSON, базу и ссылки на медиа. На большом экспорте дождись сообщения `ГОТОВО`. Пароль передаётся приложению локально и не записывается в командную строку/файл в открытом виде.
5. Должна появиться `TelegramArchive-ready` с `bundle-manifest.json`, `app/`, `data/archive.sqlite3`, `exports/first-export/`, `deploy/` **и** `START-LOCAL.bat`. Важно получить надпись `ГОТОВО`, а не просто новую папку: при ошибке может остаться **неполная папка**.
6. Дважды кликни **`TelegramArchive-ready/START-LOCAL.bat`** (он там уже есть). Открой **`http://127.0.0.1:8000`** и введи пароль. Остановить: `Ctrl+C` в консоли. На Windows это **локальный доступ только с твоего компьютера**, не для других устройств.

### Если готовая папка уже существует / не хочешь перемещать оригинал

Открой PowerShell в папке **сборщика** и выполни *вариант с копией*, если есть **свободное место, равное объёму экспорта**:

```powershell
.\build-one-folder-windows.ps1 -ExportPath "D:\TelegramExport" -BundlePath "D:\TelegramArchive-ready-NEW" -CopyExport
```

Для перемещения с указанием другого имени папки назначения (второй путь должен быть на том же диске):

```powershell
.\build-one-folder-windows.ps1 -ExportPath "D:\TelegramExport" -BundlePath "D:\TelegramArchive-ready-NEW"
```

**Если твой экспорт сейчас лежит внутри старой `TelegramArchive-ready`:** при перемещении из неё старая читалка останется без медиа. Сначала скопируй экспорт в отдельное безопасное место или продолжай пользоваться старой готовой папкой, если обновлять индекс с нуля не нужно.

### Проверка и один передаваемый файл

Если нужно повторить проверку перед передачей (останови локальную читалку):

```powershell
.\.venv\Scripts\python.exe .\bundletool.py verify --bundle "D:\TelegramArchive-ready" --full
```

**Рекомендованный вариант:** передавать всю готовую папку по **SFTP с возобновлением**. Если нужен именно один файл, можно создать `tgarchive.tar` **без сжатия**:

```powershell
.\.venv\Scripts\python.exe .\bundletool.py pack --bundle "D:\TelegramArchive-ready" --output "D:\tgarchive.tar"
```

TAR примерно такого же размера, как папка, плюс индекс. Понадобится ещё столько же места на Windows, сколько занимает папка и дополнительное место для распаковки на сервере. **TAR — переносимый архив, а не Docker-контейнер.**

### Примечания

- В готовую папку автоматически включены **все исправления v0.3**, в том числе прокрутка после поиска в обе стороны и удалённый информационный блок на главной. Отдельные патчи не нужны.
- Если в консоли ошибка — **не удаляй ни `result.json`, ни готовую папку до анализа**. Неполный пакет не загружай на сервер.
- Если ты ранее создавал `TelegramArchive-ready` старым сборщиком и всё устраивает, пересборка **не обязательна**. Этот ZIP нужен для чистой сборки или хранения полного актуального исходного кода.

### Восстановление после ошибки «файл занят другим процессом» или несовпадения паролей

**Никогда не удаляй исходный экспорт или неполную `ready`, пока не проверил обе папки.**

1. Закрой `START-LOCAL.bat`, процессы Python, открытые файлы из экспорта в VS Code и лишние окна Проводника. Проверь, **где реально лежит** `result.json`:
   - Если в исходной `D:\TelegramExport\result.json`, а внутри `ready/exports/` **нет файлов**, повтори `START-HERE.bat`. Новый скрипт безопасно использует оставшуюся пустую служебную папку и до переноса заново подтверждает пароль.
   - Если исходный `result.json` **уже перемещён** в `D:\TelegramArchive-ready\exports\first-export\result.json`, а `bundle-manifest.json` ещё нет: запусти `RESUME-READY.bat` из папки сборщика и укажи существующую `TelegramArchive-ready`. Скрипт работает **без повторного переноса экспорта**, но откажется от продолжения, если база уже частично импортирована.
   - Если данные **есть в обеих папках**, сначала выясни, полные ли они. Ничего не удаляй и не запускай повторный перенос поверх неполных данных.
2. Если `bundle-manifest.json` **есть** и локальное приложение уже работает, **не пересобирай архив из-за пароля**: останови `START-LOCAL.bat` и запусти `RESET-PASSWORD.bat` в готовой папке. Сообщения и медиа останутся без изменений.
3. Если перенос продолжает выдавать «занят другим процессом», запусти **`CHECK-LOCK.bat`** (или дождись его автоматического вызова после ошибки). Укажи папку экспорта, дай разрешение UAC и, при желании, подтверди загрузку **официального** Microsoft Sysinternals Handle. На экране и в `%TEMP%/tgarchive-lock-*.txt` появятся имена процессов, PID и открытые пути, **если обнаружены**. Наличие открытого дескриптора — не гарантия, что именно он мешает переносу; если найденных дескрипторов нет, возможны другие причины. По умолчанию всё ещё используется `Move-Item`, **hardlinks отсутствуют**.

**Ограничение:** эта версия проверена автоматическими тестами на небольшом искусственном экспорте. Перед обработкой личного архива лучше сохранить независимую резервную копию.
