# Развёртывание готового пакета на сервере без Docker

Рекомендуемый путь — **собрать/проиндексировать архив на Windows**, затем передать **готовую папку** на сервер. Это **переносимый каталог**, не контейнер Docker и не Windows `.exe`: Linux устанавливает только серверные Python-зависимости. **Экспорт на сервере повторно не индексируется.**

**Требования:** отдельный VPS с Ubuntu 22.04/24.04 или Debian 12/13, `sudo` и SSH, **постоянный публичный IPv4**, открытые TCP **80/443**, достаточно SSD для исходной папки + SQLite + резерва (ориентир — SSD примерно в 3 раза больше объёма экспорта, если там больше ничего нет). Приведённый автоматический скрипт рассчитан на **чистый сервер**; если уже работают сайты / nginx / certbot, проверь конфликты и вручную согласуй их конфигурации. Приватный экспорт будет на серверном диске **без сквозного шифрования**.

## 1. Перенести папку через WinSCP/SFTP

На Windows **останови локальный `START-LOCAL.bat` (`Ctrl+C`)** и дождись завершения. Не копируй активную SQLite с незавершённым WAL. С помощью WinSCP загрузи **содержимое** `TelegramArchive-ready` на сервер в `~/tgarchive-upload/` — вместе с `app`, `data`, `exports`, `deploy`, `bundletool.py` и `bundle-manifest.json`. Для большого экспорта папка и SFTP удобнее TAR: можно докачать недостающие файлы после сбоя.

По SSH на сервере:

```bash
mkdir -p ~/tgarchive-upload
# После полной загрузки на сервер, из SSH:
python3 ~/tgarchive-upload/bundletool.py verify --bundle ~/tgarchive-upload --full
```

Команда сверяет SHA256 JSON, количество и общий размер исходных файлов и наличие медиа. **Не является проверкой SHA256 каждого из десятков тысяч медиа.** Если нужно максимальное подтверждение передачи, дополнительно используй манифест с хешами файлов и независимый резервный бэкап.

## 2. Установить веб-приложение (без Docker)

Ниже предполагается, что `/srv/tgarchive` **ещё НЕ существует**. Сначала проверь, что там нет старого архива или чужих данных.

```bash
test ! -e /srv/tgarchive || { echo 'Already exists: review it first'; exit 1; }
sudo mv "$HOME/tgarchive-upload" /srv/tgarchive
sudo python3 /srv/tgarchive/bundletool.py verify --bundle /srv/tgarchive --full
sudo bash /srv/tgarchive/deploy/install-bundle.sh ПУБЛИЧНЫЙ_IP ТВОЙ_EMAIL
```

Вместо `ПУБЛИЧНЫЙ_IP` укажи свой IPv4, вместо `ТВОЙ_EMAIL` — адрес для уведомлений сертификата. **Запускать установщик только после полной передачи и проверки.** Он устанавливает Python, systemd-сервис, nginx, Certbot 5.4+ и настраивает HTTPS для **IP**. `tgarchive` слушает **только `127.0.0.1:8000`**; этот порт НЕ открывай извне.

**IP-сертификаты Let's Encrypt сейчас доступны**, но действуют ~160 часов, поэтому скрипт создаёт таймер регулярного продления, nginx reload hook и сначала проверяет выпуск на staging. Серверу обязательно нужен доступ по 80 для проверки владения IP. Если выпуск сертификата завершился ошибкой, **не вводи пароль через HTTP**: исправь доступность 80, версию Certbot и настройку HTTPS, затем повтори конфигурацию после изучения сообщения об ошибке.

## 3. Проверить, прежде чем пользоваться

```bash
sudo systemctl status tgarchive nginx tgarchive-cert-renew.timer --no-pager
sudo nginx -t
sudo certbot certificates
sudo certbot renew --dry-run
sudo ss -lntp | grep -E ':80|:443|:8000'
```

Далее открой **`https://ПУБЛИЧНЫЙ_IP/`** на компьютере и телефоне. Проверяй вход, поиск, перелистывание **в обе стороны**, загрузку фото и нескольких видео. На внешнем интерфейсе должен отвечать **только** nginx 80/443 (и SSH по выбранному порту); приложение 8000 — исключительно на localhost.

Если что-то не работает:

```bash
sudo journalctl -u tgarchive -n 80 --no-pager
sudo systemctl status nginx --no-pager
sudo certbot renew --dry-run
```

## Альтернатива: один TAR

Передай `tgarchive.tar` по SFTP (понадобится место и под TAR, и под распакованный набор). На сервере:

```bash
sudo mkdir /srv/tgarchive
sudo tar -xf ~/tgarchive.tar -C /srv/tgarchive --strip-components=1
sudo python3 /srv/tgarchive/bundletool.py verify --bundle /srv/tgarchive --full
sudo bash /srv/tgarchive/deploy/install-bundle.sh ПУБЛИЧНЫЙ_IP ТВОЙ_EMAIL
```

**Никогда не распаковывай TAR из недоверенного источника от root**; этот файл должен быть твоей собственной сборкой и передаваться через SSH.

## А если нужен настоящий Docker-контейнер?

**Не надо** зашивать гигабайты переписок в Docker image. В проекте есть `deploy/docker/compose.yaml`: образ собирается на сервере только из `TelegramArchive-ready/app/`; исходный экспорт и SQLite монтируются отдельно. Положи копию `compose.yaml` **рядом** с папкой `TelegramArchive-ready` на Linux и подправь права на `data/`, `exports/` для UID 10001 до запуска. Docker слушает **только `127.0.0.1:8000`**; nginx и HTTPS всё равно настраиваются на хосте. **НЕ запускай одновременно systemd и Docker на порту 8000**. Для одного частного архива рекомендован вариант **без Docker** выше: он короче и уже согласован с переносимым пакетом.

## Защита

- Пароль (Argon2id) и HTTPS — защита веб-доступа, **не шифрование диска**; делай отдельные **зашифрованные** резервные копии.
- На сервере не раздавай содержимое `exports/` и `data/` напрямую через nginx: доступ к фото и JSON контролирует FastAPI.
- Используй SSH-ключи и брандмауэр. Не выкладывай `bundle-manifest.json`, особенно вместе с приватными данными, в публичный репозиторий.
- Автотесты и эти инструкции не заменяют независимый аудит публичного веб-приложения; для действительно очень чувствительного полного архива приватный VPN-доступ (например, Tailscale) безопаснее прямой публикации по IP.
